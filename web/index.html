    Radio interface

    off

    Run the repeater on this computer's sound devices: receive audio comes in on the input, and repeated audio, tones and IDs go out on the output. Without a carrier-detect wire, the repeater can open on audio level or on a CTCSS tone.

    RX – carrier no tone TX

    The input has been pure digital silence. If you expected a signal: on macOS, the app running the server (Terminal, iTerm, Cursor…) needs Microphone permission in System Settings › Privacy & Security › Microphone, then a restart.

    Autopatch

    Let users place phone calls through the repeater. Calls go out through a SIP phone line in the Asterisk sidecar; see the setup guide.

    Call

    Loading…

    A test call goes out over the air like a DTMF-dialed one, and follows the same rules.

    Phone line

    Loading…

    Saving writes the line to Asterisk's pjsip.conf, in sections named mor-trunk…, and points autopatch at it. Other settings in that file are kept, but Asterisk removes its comments. Calls in are answered by a mor-incoming context in custom/extensions.conf (or extensions.conf without AllStarLink).
    Unsaved changes

    Calls in

    Callers get three tries at the code. Then the repeater says “Incoming phone call” and puts them on the air, with the same time limit and hang-up code as calls out. Autopatch has to be allowed above, and the provider has to be able to reach Asterisk; see the setup guide.

    Backup & restore
    
          
    A full backup holds everything needed to rebuild the repeater: settings, DTMF macros,
            announcements, audio clips, dashboard users, airtime statistics and the audit log, and optionally
            recordings. The phone line lives in Asterisk and isn't included.
